# Thesis Base Conventions

## 目的

提供跨論文共用的寫作與編修規則。任何 thesis 類 skill 都先讀這份，再視任務需要讀領域層與專案層規範。

## 讀取順序

1. 先讀目前 skill 的 `SKILL.md`。
2. 再讀本檔。
3. 只有當任務明確涉及對應領域時，才讀 `statistics_thesis_conventions.md` 或其他領域層規範。
4. 若 workspace 內存在 `.agent/references/thesis_project_conventions.md`，最後讀它並以其內容覆寫前述慣例。

## 核心原則

- 先界定任務是「規劃、成稿、審查、編譯」中的哪一類，再決定要不要動正式稿。
- 先讀現有稿件，再補寫內容；禁止在沒看過既有章節風格時直接重寫整節。
- 未驗證前，不得捏造 citation key、文獻結論、數值結果、定理條件、圖表內容或實驗設定。
- 若資料不足以支撐強 claim，降低語氣並明示限制，不要硬補推論。
- 優先維持專案既有結構、巨集、排版習慣與符號系統，不要把自己的偏好覆蓋到稿件上。

## Source Of Truth

- 正式章節內容以論文專案內的正式稿檔案為準，例如 `.tex`、`.qmd`、`.typ`。
- 草稿、筆記、條列式規劃僅作為候選素材，不自動凌駕正式稿。
- 若正式稿與草稿衝突，先標記衝突點，再依專案慣例決定採用哪一邊。

## 規劃與成稿分流

- 規劃任務優先輸出 outline、段落功能、claim-evidence 對照、缺口清單。
- 成稿任務才寫正式段落與公式環境。
- 未獲使用者同意時，避免直接大幅覆寫正式稿；優先在草稿區或回覆中提出結構化候選內容。

## 引用與證據

- 只使用已存在且已核實的 citation key。
- 若需要新增文獻，先確認 bibliographic metadata 與實際主張是否匹配，再新增。
- 每個核心 claim 都要能指出對應文獻、數學推導、實驗結果或明確限制。

## 編輯前檢查

- 讀 entry file、preamble/style 檔、目標章節、相鄰章節。
- 確認稿件目標語言與目前章節語氣，不要自動換語言。
- 確認目前章節在整篇論文中的角色，避免把 introduction、background、methodology 寫成重複內容。

## 輸出規則

- 與使用者協作時，使用使用者要求的語言；若使用者沒有指定語言，跟隨目前對話語言。
- 插入正式稿的內容必須匹配稿件當前主語言。
- 保留 unresolved items，明列缺的 citation、缺的定義、缺的實驗或待確認的假設。

## 讀者導向寫作偏好

- 對讀者可能卡住的符號切換、估計對象切換或證明跳步，優先補短 prose bridge；不要一開始就改成大型 symbol table，除非使用者明確要求。
- 新符號、向量、矩陣或線性算子第一次出現時，先說明它在當前段落中的角色；尤其要區分 centered smoother 與未中心化 smoother、單一 smoother 與整個 backfitting 收斂後的線性轉換、觀測到的 response \(y\) 與真實平均向量。
- 優先用正面定義說明對象代表什麼，少用「它不是什麼」的 meta-commentary；只有在讀者容易誤解時才補必要的對照。
- 用詞要自然但嚴謹。避免生硬或過度抽象的中文術語；若可用「bias 要控制的是……」、「平均上留下的差距」、「這個條件表示……」說清楚，就不要改寫成更僵硬的名詞堆疊。
- 不要自創沒有文獻根據或前文定義的術語，例如 `operator-level`、`低秩修正分解` 這類說法。若文獻或稿件前文沒有固定名稱，優先用一般句子描述其數學形式或作用。
- 不要硬把英文論文慣用語直譯成生硬中文；例如英文常見的 `particularly` 不必翻成「特別地」。若語氣只是要銜接例外、補充或重點，改用「其中」、「在此情況下」、「更具體地」或直接刪去。
- 不要為了讓文字看起來學術而自創英文術語或英文複合詞。若專有名詞不是文獻、課本或稿件前文已經使用的說法，就改用直白中文描述；必要的英文術語需能對應到 citation、source paper 或本章已定義的記號。
- 論文正文不需要處處重述完整技術條件。若條件在前文已清楚交代，可直接引用前文或文獻；若是第一次使用，至少用一句話列出條件類型，讓讀者知道依賴的是 density、kernel、moment、smoothness、bandwidth、interior point 等哪一層假設。
- 證明看起來簡單或直覺時，仍要補出非自動成立的關鍵原因；例如單一 smoother 的性質不必然推出整個 backfitting 解作用後每一列都受到同樣控制。

### 具體寫作修法

- 問題類型：連接詞重複，句子一路用「並且」、「因此」、「而」串下去。
  - 避免寫法：`本文假設 A，並且 B，並且 C。`
  - 建議寫法：拆成幾個層次，例如「本文在以下討論中採用兩個簡化前提。第一，A；第二，B。此外，C。」若後一句是在前提下推出結論，可用「在這些設定下」銜接。
- 問題類型：把英文學術語氣硬翻成中文。
  - 避免寫法：為了對應英文 `particularly`、`signal`、`in-sample`，直接寫成「特別地」、「additive signal」、「樣本內」等不自然說法。
  - 建議寫法：先判斷中文段落真的需不需要該詞。可改成「其中」、「更具體地」、「真實函數值」、「在資料點上計算」；若刪掉不影響意思，就直接刪去。
- 問題類型：自造或過度抽象術語。
  - 避免寫法：沒有文獻或前文定義時使用 `operator-level`、`低秩修正分解`、`signal 層級` 等看似正式但不穩的詞。
  - 建議寫法：改用句子說明數學對象或作用，例如「這個式子把 Exact smoother 與近似 smoother 的差異拆開」。
- 問題類型：過度工程化用語。
  - 避免寫法：「初始化亂數流」、「覆蓋檢查位置」、「執行 coverage verification」。
  - 建議寫法：「設定 seed」、「coverage 檢查用的格點」、「做一個 coverage 檢查」。若名詞本身很卡，重組整句，不要硬找中文對應詞。
- 問題類型：太多 meta-commentary。
  - 避免寫法：連續使用「注意這裡不是……」、「這裡的意思不是……」、「此處只是……」。
  - 建議寫法：優先直接說正面定義；只有在讀者容易混淆兩個對象時，才補一句對照。
- 問題類型：不自然的對比結語。
  - 避免寫法：把段落收在「重點不是……而是……」這種模板句。
  - 建議寫法：直接寫觀察結果與意義，例如「這表示 Nys-c 的優勢主要出現在樣本數增加後的計算成本，而它的估計分布仍接近 Exact。」
- 問題類型：圖說和圖形用語過硬。
  - 避免寫法：`panel`、「面板」、「箱體」、「Tukey outlier」。
  - 建議寫法：正文與 caption 統一寫「子圖」。箱型圖可寫成「盒子的上下緣為第一與第三四分位數，中線為 median，空心點為箱型圖標出的離群點」；若讀者不需要細節，caption 只寫「診斷指標分布」即可。
- 示範案例：若原句為「本文假設離散化後的 smoother 與連續積分定義下的 exact smoother 足夠接近，其差異相對於本文討論的 Nystr\"om 近似影響可忽略，並且後續凡使用反矩陣之處，均假設相應矩陣可逆，並且本節所使用的 \(H^*\) 滿足第二章已整理的 local linear integrated smoother 結構性質：」，可改成：
  - 「本文在以下討論中採用兩個簡化前提。第一，離散化後的 smoother 與連續積分定義下的 exact smoother 足夠接近，其差異相對於本文討論的 Nystr\"om 近似影響可忽略。第二，後續凡涉及反矩陣之處，均假設相應矩陣可逆。在這些設定下，本節使用的 \(H^*\) 滿足第二章整理的 local linear integrated smoother 結構性質：」

## 常見失敗模式

- 把規劃內容直接當成正式論文語句貼進稿件，導致語氣失衡。
- 把 literature review 寫成文獻摘要堆疊，而不是研究缺口導向。
- 把數學直覺直接升格成 theorem-level claim。
- 為了補段落完整性而虛構 citation 或實驗細節。
