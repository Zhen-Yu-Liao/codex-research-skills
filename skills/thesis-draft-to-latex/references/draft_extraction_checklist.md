# Draft Extraction Checklist

從草稿、Markdown、條列筆記或口語說明轉成正式稿前，先抽取以下資訊：

1. 這段真正要主張什麼。
2. 哪些內容只是背景鋪陳，哪些才是核心貢獻。
3. 哪些符號、估計對象、資料欄位或實驗設定必須保留。
4. 哪些 citation key 已存在，哪些只是作者口頭提及。
5. 哪些句子其實是 TODO、placeholder、提醒或未驗證假設。
6. 哪些內容應留給 limitation 或 future work。

## 建議做法

- 先把條列與零散句子分成 claim、evidence、notation、citation、gap 五類。
- 若草稿資訊不足以支撐完整段落，先回報缺口，不要硬補 prose。
- 若草稿同時混有規劃與成稿內容，先切出可直接落稿的部分，再把其餘部分退回 planning。
